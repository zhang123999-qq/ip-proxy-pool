# 反爬方案

> 本项目的免费代理源都是公开页面，但仍有反爬机制（频率限制、UA 校验、风控页面等）。
> 本方案说明已采取的所有反爬措施，以及为什么这样做。

---

## 一、目标

让爬虫「**像人一样**」访问目标站点：

- 不会被 1 秒内识别为爬虫
- 不会触发频率限制封 IP
- 不会因为内容变化而解析失败

---

## 二、已实施的反爬手段

### 1. 真实浏览器请求头 ✅

```
User-Agent:     每次随机（Chrome / Firefox / Safari / 移动端）
Accept:         text/html,application/xhtml+xml,...
Accept-Language: zh-CN / en-US / ja / 多语种随机
Accept-Encoding: gzip, deflate
Referer:        谷歌 / 必应 / 百度 / 搜狗 随机
Connection:     keep-alive
Upgrade-Insecure-Requests: 1
```

**为什么**：免费代理源最常见的风控就是 UA 白名单（只放行 Chrome）和 Referer 校验。

### 2. 全局限速令牌桶 ✅

每秒最多 `CRAWL_RATE_PER_SEC` 个请求（默认 2 个），通过令牌桶算法平滑突发。

**为什么**：突发 10 个请求 100% 触发风控，2 个/秒很难被识别。

### 3. 单源随机延时 ✅

每次请求间隔 `1~3 秒` 随机。

**为什么**：真人浏览页面会有 1-5 秒思考时间。

### 4. 单源失败熔断 + 指数退避 ✅

- 连续失败 `CRAWL_MAX_FAIL=3` 次 → 熔断 5/10/20 秒
- 单次请求内：3 次重试，每次失败退避 5/10 秒

**为什么**：源站点一旦判定为爬虫，所有后续请求都会失败。熔断能给站点"冷静期"。

### 5. HTTP 状态码敏感 ✅

| 状态码 | 处理 |
|--------|------|
| 200 | 正常 |
| 403/429/503 | 视为被风控，立即退避重试 |
| 5xx | 网络问题，重试 |
| 连接超时 | 重试 |

### 6. 协议头噪声 ✅

- `Cache-Control: max-age=0`（像首次访问）
- `Upgrade-Insecure-Requests: 1`（真实浏览器标志）
- 移动端 UA 加上 `Sec-Fetch-Dest / Sec-Fetch-Mode`

### 7. 翻页（适用结构）✅

快代理分页拉取 2-3 页，源稳定时一次性能拿更多。

### 8. 编码自适应 ✅

`resp.encoding` 为空或 ISO-8859-1 时用 `apparent_encoding`（chardet）推断。

**为什么**：66ip 等站是 GBK，不处理会乱码。

### 9. 单源故障隔离 ✅

每个爬虫被 manager 单独包裹，1 个源挂了不影响其他 6 个。

### 10. 日志分级 ✅

- 解析失败：WARN（带堆栈但不全量）
- 网络异常：DEBUG（频繁且不影响业务）
- 采集成功：INFO

---

## 三、主动避免的反爬触发点

| ❌ 不要做 | ✅ 应该做 |
|----------|----------|
| 1 秒内并发 50 个请求 | 全局限速 2 req/s |
| UA 永远不变 | 每次随机 UA |
| 不带 Referer | Referer 随机 |
| 失败重试无限次 | 最多 3 次 + 退避 |
| 不管状态码继续冲 | 403/429 立即退避 |
| 共享一个 cookie 池 | 每个源独立（无 cookie） |
| 失败后继续高频重试 | 熔断 N 秒后重试 |

---

## 四、采集策略

```
┌──────────────────────────┐
│ 1. 拿令牌 (限速)         │
│ 2. 熔断检查 (跳过)        │
│ 3. 随机延时 1-3s         │
│ 4. 拼装浏览器头           │
│ 5. 发送请求               │
│ 6. 状态码判断             │
│    ├ 200 → 解析           │
│    ├ 403/429/503 → 退避   │
│    └ 其他异常 → 退避       │
│ 7. 解析 → 入池            │
└──────────────────────────┘
```

## 五、监控指标

每个爬虫在日志里输出：
- `采集到 N 条`（成功）
- `解析失败: ...`（结构变化）
- `HTTP 403/429/503`（被风控）
- `熔断 Ns`（触发熔断）
- `重试 N 次仍失败`（长期不可用）

管理员可以根据这些信号下线/替换失活的源。

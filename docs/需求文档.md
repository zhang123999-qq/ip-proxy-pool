# IP 代理池 - 需求文档

> 版本：v1.0
> 日期：2026-09-06

---

## 一、项目背景

免费代理 IP 在网络爬虫、数据采集、匿名访问等场景中有广泛应用。但免费代理普遍存在**质量不稳定、失效快、匿名度低**等问题。本项目旨在构建一个**自动采集 + 实时打分**的代理池系统，自动维护高质量代理，提升业务可用性。

## 三、功能需求

### 3.1 代理采集 (FR-01)

- **FR-01.1** 支持从至少 3 个免费代理源采集 IP
- **FR-01.2** 采集时自动去重（按 ip:port）
- **FR-01.3** 异步并发采集，单批采集耗时 ≤ 30 秒
- **FR-01.4** 采集失败时自动重试（最多 3 次）
- **FR-01.5** 支持用户自定义代理源（可扩展）

### 3.2 代理验证 (FR-02)

- **FR-02.1** 验证代理是否可连通
- **FR-02.2** 记录响应时间（用于后续排序）
- **FR-02.3** 单次验证超时 ≤ 10 秒
- **FR-02.4** 验证采用并发方式
- **FR-02.5** 区分 HTTP 与 HTTPS 支持

### 3.3 实时打分制 (FR-03) ⭐ 核心

#### 3.3.1 分数规则

| 行为 | 分数变化 | 说明 |
|------|---------|------|
| 初始入池 | **10 分** | 验证通过即入库 |
| 验证可用 | **+1 分** | 后台定期验证 |
| 验证失败 | **-3 分** | 后台定期验证 |
| 业务使用成功 | **+1 分** | 调用方主动反馈 |
| 业务使用失败 | **-3 分** | 调用方主动反馈 |
| 分数 ≤ 0 | **自动删除** | 移出代理池 |

#### 3.3.2 反馈方式

- **主动反馈 API**：`POST /proxy/feedback` 参数 `{ip, port, success: bool}`
- **被动验证**：系统定期（每 5-10 分钟）回访验证

#### 3.3.3 分数上限

- 最高分数建议封顶 20 分（避免单一代理过度信任）

### 3.4 代理池存储 (FR-04)

- **FR-04.1** 内存存储结构：`{proxy_key: ProxyItem}`
- **FR-04.2** **线程 + 协程双重并发安全**（asyncio.Lock + threading.RLock）
- **FR-04.3** 支持持久化到本地文件（重启恢复）
- **FR-04.4** 提供查询、添加、删除、更新分数等操作
- **FR-04.5** 持久化采用**原子写**（tempfile + os.replace），断电不损坏
- **FR-04.6** 入库时校验 IP/端口合法性
- **FR-04.7** 单条 ProxyItem 字段读写受 RLock 保护

### 3.5 API 服务 (FR-05)

| 路径 | 方法 | 描述 |
|------|------|------|
| `/health` | GET | 健康检查 |
| `/proxy/count` | GET | 获取当前代理数量 |
| `/proxy/stats` | GET | 池统计（平均/最高/最低分 + 协议分布） |
| `/proxy/random` | GET | 加权随机获取代理（支持 protocol/min_score 过滤） |
| `/proxy/batch` | POST | 批量获取 N 个不重复代理 |
| `/proxy/all` | GET | 分页获取所有代理（按分数倒序） |
| `/proxy/top` | GET | 分数最高 N 个 |
| `/proxy/feedback` | POST | 反馈代理使用结果（影响分数） |
| `/proxy/remove` | POST | 主动删除代理 |
| `/proxy/refresh` | POST | 手动触发采集 + 验证 |

#### 3.5.1 数据校验

- IP 必须为合法 IPv4（pydantic 校验）
- port 范围 1-65535
- min_score 范围 0-20

### 3.6 调度任务 (FR-06)

- **FR-06.1** 每 10 分钟触发一次代理采集
- **FR-06.2** 每 5 分钟触发一次代理验证（已入池代理）
- **FR-06.3** 每 1 小时持久化一次到磁盘

## 四、非功能需求

### 4.1 性能要求
- 单次获取代理 API 响应时间 ≤ 100ms
- 代理池容量 ≥ 100 个（视采集情况）
- 采集 + 验证完整流程 ≤ 5 分钟

### 4.2 可靠性
- 采集失败不影响代理池已有数据
- 单个代理源失败不影响其他源
- 支持优雅停机（保存数据后再退出）

### 4.3 可维护性
- 模块化设计，各模块独立可测试
- 配置项集中管理（config.py）
- 提供完善的日志（INFO/WARN/ERROR）

### 4.4 兼容性
- Python 3.10+
- Windows / Linux / macOS 跨平台

## 五、接口设计示例

### 获取代理

```http
GET /proxy/random
```

响应：
```json
{
  "code": 0,
  "data": {
    "ip": "1.2.3.4",
    "port": 8080,
    "protocol": "http",
    "score": 12,
    "response_time": 0.85
  }
}
```

### 反馈使用结果

```http
POST /proxy/feedback
Content-Type: application/json

{
  "ip": "1.2.3.4",
  "port": 8080,
  "success": true
}
```

响应：
```json
{
  "code": 0,
  "msg": "feedback success",
  "data": {
    "ip": "1.2.3.4",
    "port": 8080,
    "new_score": 13
  }
}
```

## 六、验收标准

- [ ] 系统可自动从至少 3 个免费代理源采集 IP

- [ ] 分数 ≤ 0 的代理自动从池中删除
- [ ] 提供完整 RESTful API
- [ ] 定时任务正常运行（采集 + 验证）
- [ ] 重启后代理池数据可恢复
- [ ] 关键操作有日志记录
- [ ] 项目结构清晰，文档齐全
